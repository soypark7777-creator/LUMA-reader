# LUMA OCR 페이지 개선 작업계획서

## 1. 현재 진단

`http://localhost:5000/ocr`는 이미지 업로드, OCR 추출, 텍스트 개선, 책 정보 감지, 메모 생성, 분석 실행까지 한 화면에서 처리한다. 기능 범위는 넓지만 사용 흐름이 조금 섞여 있어 사용자가 “추출 → 다듬기 → 책 정보 확정 → 분석/저장” 순서를 명확히 이해하기 어렵다.

현재 개선이 필요한 핵심 문제는 다음과 같다.

- OCR 후 자동 책 정보 감지가 사용자가 직접 입력한 책 제목을 덮어쓸 수 있다.
- 작가 입력 필드가 화면에 없어 분석 payload와 UI가 어긋난다.
- 텍스트 개선 prompt 일부가 깨진 문자열이라 문장 다듬기 품질이 불안정하다.
- OCR 원문과 다듬은 문장을 비교하기 어렵다.
- 분석 결과가 메모, 주제, 질문, 참고자료로 분리되어 보이지 않아 활용성이 낮다.
- 화면 문구와 일부 UI 텍스트가 깨져 신뢰감이 떨어진다.

## 2. 1차 수정 완료 범위

이번 1차 수정에서는 OCR의 기본 흐름을 안정화한다.

- `/ocr` 화면의 OCR 요청을 `/api/ocr/scan`으로 연결한다.
- `/api/ocr/status`를 기준으로 Google Vision/fallback 상태를 표시한다.
- 사용자가 직접 입력한 책 제목과 작가는 자동 감지 결과가 덮어쓰지 않게 한다.
- 작가 입력 필드를 추가한다.
- 텍스트 개선 API에 `book_title`, `book_author`를 함께 전달한다.
- 문장 다듬기 prompt를 정상 한국어로 교체한다.
- 메모 생성 prompt가 사용자가 입력한 책 제목을 기준으로 분석하도록 보정한다.

## 3. 디자인 개선 방향

OCR 페이지는 “광학 실험실” 느낌보다 “독서 문장 정리 도구”에 가까워야 한다. 디자인은 어둡고 장식적인 배경을 줄이고, 반복 사용에 편한 작업대 형태로 재구성한다.

### 레이아웃

- 좌측: 이미지 업로드 및 미리보기
- 중앙: OCR 원문과 다듬은 문장 비교
- 우측: 책 정보, 분석 요약, 저장 액션
- 모바일에서는 업로드 → 텍스트 → 책 정보 → 분석 순서의 단일 컬럼으로 배치

### UI 구성

- OCR 원문과 다듬은 문장을 탭 또는 좌우 비교로 제공
- “원문 유지”, “다듬은 문장 적용”, “다시 다듬기” 버튼 제공
- 책 제목/작가/쪽수는 분석 전 확인해야 하는 고정 패널로 배치
- 분석 결과는 `핵심 문장`, `주제`, `감정`, `질문`, `태그`로 분리
- 저장 버튼은 분석 완료 후 명확히 활성화

### 시각 톤

- 배경은 차분한 딥 네이비/먹색 계열을 유지하되 장식적 광원은 줄인다.
- 입력/결과 영역의 대비를 높여 긴 문장 읽기에 집중하게 한다.
- 버튼은 기능별로 색을 분리한다: 추출, 다듬기, 분석, 저장.
- 카드 중첩을 피하고 작업 패널 단위로만 구분한다.

## 4. 기능 개선 계획

### Phase 1. OCR 입력 안정화

- 이미지 업로드 시 파일명, 크기, 해상도 표시
- Google Vision 결과가 비어 있으면 사용자에게 “텍스트 없음”과 재촬영 가이드 표시
- 이미지 전처리 옵션 추가: 회전, 대비 강화, 잘라내기
- 업로드 이미지가 책 표지인지 본문 페이지인지 사용자가 선택 가능하게 구성

### Phase 2. 문장 다듬기 고도화

- OCR 원문과 개선문을 동시에 보이게 한다.
- 다듬기 강도를 3단계로 제공한다.
- `정확 교정`: 오탈자와 줄바꿈만 수정
- `자연 문장`: 읽기 좋게 문장부호와 띄어쓰기 보정
- `메모형 정리`: 독서 메모에 붙이기 좋은 문장으로 정돈
- 변경된 부분을 하이라이트해서 사용자가 원문 훼손 여부를 확인하게 한다.

### Phase 3. 책 정보 확정 흐름

- 자동 감지 결과는 “추천값”으로만 표시하고 즉시 덮어쓰지 않는다.
- 사용자가 직접 입력한 책 제목을 항상 우선한다.
- 제목/작가로 Naver Books 검색을 붙여 표지와 메타데이터를 선택할 수 있게 한다.
- 분석/저장 payload에 확정된 책 제목, 작가, 쪽수를 일관되게 전달한다.

### Phase 4. 분석 결과 업그레이드

- 구절 분석 결과를 다음 구조로 정규화한다.
- `summary`: 이 문장이 말하는 것
- `theme`: 핵심 주제
- `emotion`: 독서 감정
- `question`: 다시 생각하게 하는 질문
- `keywords`: 태그
- `memo_draft`: 저장 가능한 메모 초안
- 사용자가 직접 입력한 책 제목을 분석 prompt에 고정 context로 넣는다.
- 분석 결과를 복사, 저장, 소크라테스 페이지로 보내기 액션과 연결한다.

### Phase 5. 저장과 데이터 흐름

- 저장 전에 실제 연결될 `book_id`, `book_title`, `page_number`를 확인하는 미니 확인 영역을 제공한다.
- 책 제목만 있고 DB에 책이 없으면 책장을 자동 생성하되, 사용자에게 생성 사실을 표시한다.
- 저장 후 `/heart`, `/social`, `/deepdive`에서 같은 책/메모가 보이는지 smoke test를 만든다.

## 5. API 개선 제안

현재 OCR API를 유지하면서 응답 구조를 점진적으로 정리한다.

```json
{
  "ok": true,
  "ocr": {
    "text": "원문",
    "source": "google_vision",
    "confidence": 0.95
  },
  "enhanced": {
    "text": "다듬은 문장",
    "changes": []
  },
  "book": {
    "title": "사용자가 확정한 제목",
    "author": "작가",
    "source": "manual|detected|search"
  },
  "analysis": {
    "summary": "",
    "theme": "",
    "emotion": "",
    "question": "",
    "keywords": []
  }
}
```

## 6. 테스트 계획

- Google Vision 키 인식: `python scripts\test_google_vision_ocr.py`
- HTTP OCR smoke test: `python scripts\test_ocr_http.py`
- `/ocr` 화면에서 책 제목을 직접 입력한 뒤 OCR을 실행해 제목이 유지되는지 확인
- 텍스트 개선 요청 payload에 `book_title`, `book_author`가 포함되는지 확인
- 메모 생성 결과가 입력한 책 제목 기준으로 나오는지 확인
- 저장 후 `/heart`와 `/social`에서 같은 책/이미지/메모가 연결되는지 확인

## 7. 우선순위

1. 깨진 UI 문구 정리와 책 제목 덮어쓰기 방지
2. 원문/개선문 비교 UI
3. 책 정보 확정 패널
4. 분석 결과 구조화
5. 이미지 전처리 도구
6. 저장 후 다른 페이지 연동 smoke test
