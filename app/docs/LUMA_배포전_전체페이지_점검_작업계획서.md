# LUMA 배포 전 전체 페이지 점검 작업계획서

## 1. 점검 목표

`http://localhost:5000/`에서 시작되는 LUMA 전체 사용자 흐름을 배포 전에 점검한다. 단순히 페이지가 열리는지만 확인하지 않고, 로그인 상태, 책 데이터 흐름, 이미지 표시, OCR, 커뮤니티, 저장/수정/삭제, 추천/분석 결과가 실제 데이터베이스와 API를 통해 일관되게 동작하는지 확인한다.

## 2. 핵심 점검 원칙

- 모든 페이지는 로그인 상태를 같은 기준으로 표시해야 한다.
- `localStorage.luma_token`, `localStorage.luma_user`가 있으면 로그인 버튼이 남아 있으면 안 된다.
- 책 제목/작가/표지 이미지는 페이지마다 같은 DB/API 흐름으로 보여야 한다.
- mock/fallback 데이터는 실제 데이터가 없을 때만 보조로 사용한다.
- 사용자가 입력한 값은 자동 감지나 추천 결과가 임의로 덮어쓰면 안 된다.
- 모바일과 데스크톱에서 버튼, 카드, 텍스트가 겹치지 않아야 한다.

## 3. 1차 발견 이슈

### `/community/` 로그인 표시

현상:

- 로그인된 상태인데도 `/community/` 상단에 로그인 표시가 계속 남아 있을 수 있다.

조치:

- `app/templates/community.html` 하단에 로그인 상태 동기화 스크립트를 추가했다.
- `localStorage.luma_token`이 있으면 `nav-user` 또는 `/auth/login` 링크를 사용자명/로그아웃 버튼으로 교체한다.

추가 확인:

- 로그인 후 `/community/` 새로고침
- 로그인 버튼이 사라지고 사용자명/로그아웃이 보이는지 확인
- 로그아웃 클릭 시 localStorage가 비워지고 `/auth/login`으로 이동하는지 확인

## 5. 공통 로그인 점검

각 페이지에서 아래 항목을 확인한다.

- 비로그인 상태에서 로그인 버튼이 보인다.
- 로그인 후 사용자명 또는 사용자 표시가 보인다.
- 로그인 후 로그인 버튼이 그대로 남아 있지 않다.
- 로그아웃 버튼이 있으면 정상 동작한다.
- API 요청에 필요한 경우 `Authorization: Bearer {token}`이 포함된다.
- 토큰 만료/유효하지 않은 토큰 상황에서 사용자에게 명확한 안내가 나온다.

브라우저 콘솔 점검:

```javascript
localStorage.getItem('luma_token')
localStorage.getItem('luma_user')
```

## 6. `/` 대시보드 점검

점검 항목:

- 오늘의 관측 리포트가 실제 사용자 데이터 기준으로 표시된다.
- 총 책 수, 메모 수, 읽기 흐름 수치가 DB/API와 맞는다.
- `/lounge` 추천 책 또는 개인 추천 데이터가 첫 화면에 자연스럽게 연결된다.
- 책 표지 이미지가 깨지지 않는다.
- 로그인 상태 표시가 맞다.

관련 API 후보:

```text
GET /api/v2/system/status
GET /api/v2/shelf
GET /api/v2/lounge/recommendations
```

## 7. `/heart` 책장/마음 행성계 점검

점검 항목:

- 등록된 책이 DB에서 불러와진다.
- 책 표지가 `/social`과 같은 수준으로 정상 표시된다.
- 책 추가가 된다.
- 책 수정이 된다.
- 수정 항목: 책 제목, 작가, 표지 이미지, 상태, 진행률
- 책 삭제가 된다.
- 삭제 후 화면과 DB가 같이 반영된다.
- 감정/메모/연결 데이터가 책과 연결된다.

중요 확인:

- Naver/Google Books 검색 결과가 있으면 실제 표지 URL을 사용한다.
- local fallback 이미지는 실제 표지가 없을 때만 사용한다.

## 8. `/lounge` 추천 흐름 점검

점검 항목:

- 개인 추천 책이 비어 있지 않게 표시된다.
- 추천 책 이미지가 정상 표시된다.
- `/`의 오늘의 관측 리포트와 추천 데이터 흐름이 이어진다.
- 추천 API 실패 시 fallback UI가 깨지지 않는다.
- 추천 카드 클릭 또는 상세 흐름이 자연스럽게 이어진다.

## 9. `/social` 생각 피드 점검

점검 항목:

- DB에 저장된 책/메모 기반 피드가 표시된다.
- 책 이미지가 정상 표시된다.
- `/heart`에 등록한 책 이미지와 표시 방식이 크게 다르지 않다.
- 메모 작성자, 책 제목, 작가, 태그가 깨지지 않는다.
- 새 메모 저장 후 피드에 나타나는지 확인한다.

## 10. `/community/` 커뮤니티 점검

점검 항목:

- 로그인 상태 표시가 정상이다.
- 참여중인 모임방 목록이 표시된다.
- 모임방 추가가 된다.
- 모임방 수정이 된다.
- 모임방 삭제가 된다.
- 모임방 상세 정보가 깨지지 않는다.
- 지도에서 한국뿐 아니라 세계 장소 검색이 가능하다.
- 장소 선택 후 모임방에 장소 정보가 저장된다.

추가 UX 확인:

- 모임방 카드가 모임 성격에 맞게 보기 좋게 정리되어 있다.
- 지도/장소 입력 UI가 모바일에서 겹치지 않는다.

## 11. `/ocr` OCR 점검

점검 항목:

- Google Vision 상태가 연결됨으로 나온다.
- 이미지 업로드 후 OCR 추출이 된다.
- 책 제목을 직접 입력하면 자동 감지가 덮어쓰지 않는다.
- 표지에서 책 정보 감지는 후보 또는 수동 입력 보조로만 동작한다.
- 텍스트 개선이 한국어로 자연스럽게 동작한다.
- 메모 초안 생성이 직접 입력한 책 제목 기준으로 나온다.
- 전체 분석과 자료 추출이 한국어 요약/주제/감정/질문/키워드로 표시된다.
- 저장 후 `/heart` 또는 `/social`에서 연결되는지 확인한다.

명령 점검:

```powershell
python scripts\test_google_vision_ocr.py
python scripts\test_ocr_http.py
```

## 13. `/socrates` 점검

- 빈 context 진입 시 기본 안내가 나온다.

## 18. 브라우저 수동 테스트 시나리오

### 시나리오 A: 로그인 후 전체 이동

3. `/heart` 이동
4. `/lounge` 이동
5. `/social` 이동

기대 결과:

- 모든 페이지에서 로그인 버튼이 남지 않는다.
- 사용자명 또는 로그아웃이 표시된다.

### 시나리오 B: 책 등록 후 전체 반영

1. `/heart`에서 책 등록
2. 책 제목/작가/표지 확인
3. `/social`에서 같은 책 이미지 확인
4. `/` 오늘의 관측 리포트 확인
5. `/lounge` 추천 흐름 확인

기대 결과:

- 책 제목과 이미지가 페이지마다 일관된다.

### 시나리오 C: OCR에서 메모 저장

1. `/ocr`에서 책 제목 직접 입력
2. 이미지 업로드 또는 텍스트 직접 입력
3. 텍스트 개선
4. 메모 초안 생성
5. 전체 분석 실행
6. 저장
7. `/heart`와 `/social`에서 저장 결과 확인

기대 결과:

- 직접 입력한 책 제목이 유지된다.
- 한국어 분석 결과가 표시된다.
- 저장된 메모가 다른 페이지에 연결된다.

### 시나리오 D: 커뮤니티 모임방

1. `/community/` 접속
2. 로그인 상태 확인
3. 모임방 생성
4. 세계 장소 검색
5. 장소 선택
6. 모임방 수정
7. 모임방 삭제

기대 결과:

- CRUD와 지도 장소 저장이 정상 동작한다.

## 19. 자동/스크립트 점검 제안

추후 `scripts/preflight_check.py`를 만들어 다음을 자동화한다.

- 주요 URL HTTP 200 확인
- 주요 API `ok: true` 확인
- OCR health 확인
- MySQL status 확인
- shelf/social/lounge 데이터 shape 확인
- static asset 404 확인

현재 1차 smoke 스크립트가 추가되어 있다.

```powershell
python scripts\preflight_check.py
```

다른 포트나 배포 URL을 확인할 때:

```powershell
python scripts\preflight_check.py --base-url http://localhost:5000
python scripts\preflight_check.py --base-url https://your-domain.example
```

추후 Playwright smoke test도 권장한다.

## 20. 배포 전 완료 기준

아래 조건을 모두 만족하면 배포 가능으로 본다.

- 주요 페이지가 모두 200으로 열린다.
- 로그인 상태 표시가 모든 페이지에서 일관된다.
- 책 등록/수정/삭제가 정상 동작한다.
- 책 표지가 `/heart`, `/social`, `/lounge`, `/`에서 정상 표시된다.
- `/community/`에서 모임방 CRUD와 지도 장소 선택이 동작한다.
- `/ocr`에서 직접 입력한 책 제목이 유지된다.
- OCR 텍스트 개선/메모/분석이 한국어로 정상 표시된다.
- MySQL 연결이 정상이다.
- Google Vision OCR 상태가 정상이다.
- 모바일/데스크톱에서 UI가 겹치지 않는다.

## 21. 배포 보류 조건

다음 중 하나라도 있으면 배포를 보류한다.

- 로그인 상태가 페이지마다 다르게 보인다.
- 책 등록 후 DB에는 저장되지만 화면에 안 나온다.
- 책 이미지가 주요 페이지에서 깨진다.
- `/community/`에서 로그인 버튼이 로그인 후에도 계속 남아 있다.
- `/ocr`에서 직접 입력한 책 제목이 다른 제목으로 바뀐다.
- OCR/메모 저장이 실패해도 사용자에게 안내가 없다.
- MySQL이 mock/fallback으로만 동작한다.
- 모바일 화면에서 주요 버튼이 가려진다.
